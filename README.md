# 透析照护助手

给**透析患者和家属**用的护理记录工具。以**透析中血糖监护**为主线：把每次透析从上机到下机的血糖按分钟记清楚、把不对劲的地方早点看出来、把要说给医生听的话整理成一页纸。

仓库地址：<https://github.com/oscar-wang-xin/dialysis>

- 手机优先，一个 HTML 文件，双击就能开、微信里能开、没网也能开
- 零依赖：无后端、无账号、无 CDN、无统计脚本、不预加载外链
- 记录只存在使用者本机的浏览器里，可导出 JSON / CSV，可打印成 A4

---

> **先把边界说清楚。** 这是护理记录与陪护辅助工具，**不是医疗器械，不作诊断、不给用药剂量、不解释化验单、不调整透析参数、不做危急值判定**。所有「异常提示」只对照医生事先给定的目标范围或症状核对清单，结论一律指向「联系透析中心 / 急诊 / 120」。出现急症请立即联系透析中心或拨打 120，不要等工具提示。

---

## 快速开始

**最省事的办法**：把根目录的 `index.html` 发到手机上（微信文件传输、网盘、数据线都行），用浏览器打开即可。也可以直接在电脑上双击。

想放到手机桌面：用浏览器打开后选「添加到主屏幕」。建议用系统浏览器打开，微信内置浏览器清数据时可能把本地记录一起抹掉。

可选：想用本地服务器预览，在仓库目录执行 `python -m http.server 8000`，然后访问 `http://localhost:8000/`。**这不是必需的**，`file://` 下所有功能都能用。

第一次打开请做两件事：

1. 进「数据与设置」填透析中心电话、急救电话（默认 120）、干体重；
2. 按透析中心的**书面交代**填监测间隔与医生给的目标范围。**这些值默认是空的，工具不会替你猜。**

## 主要功能

### 透析中血糖监护（核心）

横轴不是日历，是「**已透析 X 分钟 / 剩余 Y 分钟**」。只有这个坐标才能回答医生真正要问的那句：是不是每次都在同一段掉下来。

- 上机 → 按医嘱间隔测 → 透析末期加测 → 下机 → 透析后加测，一条按分钟排的时间轴
- 一键记血糖、标症状、记加餐、记血压，数值自动带上时刻与剩余分钟
- 症状出现时页面第一个按钮是「告知透析室工作人员」，第二个才是记录
- 当次曲线 + 历次叠加，看数值下降是不是总落在同一时段
- 到期提示只说「该测血糖了」，一键出**透析中血糖监护单**，A4 单页直接递透析室

### 其余模块

| 模块 | 做什么 | 坚决不做什么 |
| --- | --- | --- |
| 每日记录 | 体重、血压、血糖（带场景标签）、饮水尿量、体温、进食加餐、症状、备注 | 不自动判定高低 |
| 透析日志 | 上机下机、透前透后体重、超滤量照抄透析单、按时间点的血糖血压、事件与转归 | 不推算、不建议参数 |
| 化验结果 | 项目名、数值、单位、参考范围、日期、来源；按项目看趋势 | 不解释指标含义 |
| 趋势图 | 手写 SVG 折线，7 / 30 / 90 天，透析日竖线，图下永远附数据表 | 不预测、不给风险指数 |
| 问题排查 | 红 / 黄 / 绿三级核对清单，红色首屏就是拨号按钮 | 不列鉴别诊断、不推荐药物 |
| 用药打卡 | 家属照处方自维护药单，今天吃没吃打勾 | 不生成用药方案 |
| 知识库 | 内置常识卡、医院宣教 22 条与常用口服药 38 条链接索引、搜索与兜底路径 | 不收偏方、不写剂量 |
| 就诊摘要 | 一页纸汇总异常事件、数值要点、化验变化、用药、待问医生清单 | 不写「印象 / 诊断」栏 |

打印共四种 A4 视图：周记录表、透析事件单、就诊摘要、透析中血糖监护单。手机上用「分享 → 打印 / 存储为 PDF」。页脚固定印「仅供就诊沟通参考，非医疗诊断」。

## 四条硬规矩

1. **不内置任何医学数值。** 血糖阈值、监测间隔、加测点、补糖量、透析液葡萄糖浓度，一个都不写死。`monitoring` 与 `targets` 默认全空，由家属照透析中心书面交代填写，还留一栏记「谁交代的」。公开资料里能查到的间隔与阈值彼此打架、且多为二手转述，家里用的东西只认主管医生写下来的那条线。
2. **提醒只说「该测血糖了」。** 没填提醒线就完全不做数值判定；填了也只标「低于你设的线」。
3. **不承诺后台推送。** 手机浏览器切后台会冻结计时器，页面提醒只在工具打开时有效，建议同时用手机自带闹钟兜底。
4. **症状出现即现场处置。** 不替代现场医护、不远程指挥。

## 数据与隐私

- 全部记录写在本机 `localStorage`（键 `dialysisCare.v1`），不上传、不联网回传。
- **每周导出一次 JSON 是硬要求，不是可选项**：手机清缓存、换设备、微信内置浏览器清数据都可能抹掉记录。首页超过 7 天没备份会温和提醒一次。
- 导入 JSON 会二次确认并自动留旧快照；另有 CSV 导出（Excel 可开）、演示数据（明标虚构、可恢复、可清空）。
- 默认档案全空：不预填姓名、不预填任何数值。
- 详见 **[docs/PRIVACY.md](docs/PRIVACY.md)**。贡献者请务必先读，PR 里不要出现任何真实患者数据。

**改源码，别直接改 `index.html`**：它是构建产物，下次构建会覆盖。

```bash
python tools/build.py
```

构建会自检：外部资源引用、脚本闭合、链接条数（38 + 22）、隐私关键词。任何一项不过就不写产物。需要 Python 3，无第三方依赖。

## 配套 Skill

`skill/` 是给 AI 立的规矩：工具负责存数据，Skill 负责「怎么说话、什么时候闭嘴」——只描述事实与变化、急症先让打电话、生成就诊摘要与待问医生清单；不诊断、不推测病因、不建议剂量、不解释化验单、不拿「应该没事」糊弄人。

安装：把 `skill/` 整个目录复制到 `~/.workbuddy/skills/dialysis-care/`（**建真实目录，不要用软链**），重启会话后按触发词调用。Skill 只处理使用者主动导出的 JSON，不读取本机浏览器存储。

## 知识库链接的已知边界

`data/qr-links.json` 来自两张医院公开宣教海报的二维码解码，只作索引：

- **主题名和药名没有逐条和海报原图核对**，仓库里只保留编号、链接与来源，不猜测内容、不写剂量。欢迎 PR 补充核对结果。
- 药物表 38 条是草料活码短链，宣教树多为微信内内容或短链中转页。浏览器打开的可能只是中转页，部分内容需要在微信里打开。工具给三条兜底：直接点、复制链接用另一台设备打开、扫医院墙上的海报原图。
- 药物表底部的公开业务电话（药学部 85323591）照抄进工具，做成可编辑字段，方便各家医院改成自己的号码。
- 海报原图版权归原作者/医院，默认不入库；确认可公开分发后再单独添加。

## 贡献

欢迎提交 Issue 和 PR，尤其是：链接主题名核对、无障碍改进、打印样式适配更多机型、多语言。

**唯一的硬规矩**：PR 里不得包含任何真实患者数据（姓名、病历号、检查报告、化验单照片、带真实数值的截图、导出的记录文件）。测试数据一律用一眼看得出是虚构的值，并在 PR 描述里说明。维护者会按 `.gitignore` 与 `docs/PRIVACY.md` 逐项检查。

开发计划与验收标准见 [docs/DESIGN.md](docs/DESIGN.md)，版本记录见 [CHANGELOG.md](CHANGELOG.md)。
