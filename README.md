# 透析 · 家庭照护工具包

给**透析患者和家属**用的离线护理工具包。出事看应急，平时管吃饭，每天记一笔，要查资料翻知识。

仓库地址：<https://github.com/oscar-wang-xin/dialysis>

- **六张独立 HTML 页面**，不是 App、不是单页应用：一个封面 + 五张工具页，整目录拷到手机就能用
- **零依赖**：无后端、无账号、无 CDN、无统计脚本、不预加载任何外链；断网照用，双击就开
- **数据全在本机**：六张页面共用一份 `localStorage`（键 `dialysis.v1`），可导出备份、导出文本给医生、可打印
- **知识内容完整保留**：9 张护理常识卡、红/黄/绿三级排查、5 条常见情况速查，以及两张公开宣教海报上 **60 个二维码**的标题索引（22 条宣教 + 38 条药名）

---

> **先把边界说清楚。** 这是家庭照护的提醒与记录工具，**不是医疗器械，不作诊断、不给处方、不解释化验单、不调整透析参数**。页面里写的应急步骤和常见数值，是给家属「第一时间照着做、别临场想」的提醒；所有病情判断、用药和透析方案，一律以主管肾内科医生和透析中心的意见为准。出现大出血、意识不清、呼吸困难、持续胸痛，立即拨打 120。

---

## 快速开始

1. 把**整个仓库目录**（至少是根目录这 6 个 `.html`）传到手机：微信发给自己、网盘、数据线都行。
2. 用**手机自带浏览器**打开 `index.html`。别在微信里直接点开，微信内置浏览器存不住数据。
3. 安卓浏览器：菜单 →「添加到主屏幕」；iPhone Safari：分享 →「添加到主屏幕」。以后点桌面图标就能开，断网也能看。
4. 头一天先把三件事做完：在综合卡「应急」页填好透析中心、主治医生、家属三个号码；在「陪护」页把正在吃的药和每周透析日填上；点一次「导出备份文件」存到微信收藏。

电脑上双击 `index.html` 即可，不需要起服务；部署到服务器见下一节。

### 部署到静态服务器

6 张页面全是小写英文文件名，入口固定 `index.html`，可以直接放到任意静态托管：Nginx / Apache / GitHub Pages / 对象存储静态站点 / 任意 `python -m http.server`。

```bash
python -m http.server 8000
# 浏览器打开 http://localhost:8000/index.html
```

- 六张页面用相对链接互跳，换域名、放子目录都不用改代码；**别只传一个 HTML**，六张要一起传。
- 纯静态，没有后端、路由重写、环境变量，服务器上也不需要 Python（Python 只在本地构建时用）。
- 建议配 HTTPS：部分浏览器只在安全上下文里允许「添加到主屏幕」和长期本地存储。
- 数据仍只存在访问者本机浏览器里，服务器收不到、也不保存任何健康记录。
- 仓库不含任何机构名称、科室抬头、业务电话；应急页里的透析中心 / 主治医生 / 家属号码是空白输入框，由使用者自己填，只存本机。

## 六张页面

| 页面 | 干什么 |
| --- | --- |
| `index.html` | 封面与五个页面入口。装到桌面时建议收藏这一张。 |
| `care-card.html` | **日常主入口**。底部五个板块：应急 / 饮食 / 记录 / 陪护 / 说明，带夜间模式。 |
| `emergency.html` | 深色大字版，七种情况照着做，顶上就是 120。出事时只看这一页。 |
| `daily-log.html` | 台账式记录：透前透后体重、血压、血糖、尿量、超滤；体重与血糖两张走势图；可打印、可导出。 |
| `knowledge.html` | 护理常识、问题排查、60 条公开宣教二维码标题索引，支持搜索。 |
| `guide.html` | 怎么装到桌面、头三天做什么、每天怎么用、数据会不会丢。 |

六张页面**共用同一份本地数据**：在综合卡填的号码，应急速查卡直接能拨；在综合卡记的一笔，每日记录页的台账和走势图同步显示；夜间模式在任意页面切换，其他页面跟着变。

## 功能一览

**应急**（综合卡 01 / 速查卡）：120 一键拨号、透析中心与家属号码（可填写保存、自动变成 `tel:` 链接）、七种情况的「看这些表现 → 一二三四步 → 千万不要」：透析中低血糖、导管感染寒战发热、导管滑脱大出血、内瘘出血摸不到震颤、高钾手脚发麻胸闷、透析后低血压、抽筋。

**饮食**（综合卡 02）：焯水去钾的做法、尽量不吃 / 限量吃 / 低血糖救急专用三类清单、每天能喝多少水、高磷食物与磷结合剂随餐提醒。

**记录**（综合卡 03 / 每日记录页）：日期、透前透后体重、血压、血糖＋测量时点、尿量、超滤、症状多选、备注；历史台账、体重走势、血糖走势（3.9 虚线，低于它的点标红）、导出文本给医生、JSON 备份与恢复、A4 打印。

**陪护**（综合卡 04）：吃药清单（药名 / 时间 / 剂量 / 注意）、每周透析排班与时段、出门打包勾 checklist、下次复诊要问的问题、数据备份与恢复。

**知识**（知识页）：9 张常识卡、红黄绿三级排查、5 条常见情况速查，以及 60 条带标题的公开宣教链接，可按药名 / 主题 / 症状搜索。仓库不收录任何机构名称、科室名与业务电话。

**打印**：每日记录页与知识页都做了打印样式，自动隐藏按钮、工具栏和搜索框，A4 黑白清楚。

## 关于页面里的医学数值

这一版**以「透析」目录下那套家庭照护工具为模板和功能基线**，因此保留了其中常见的公开照护要点，例如「低于 3.9 mmol/L 补 15 g 葡萄糖」「蔬菜开水焯 3 分钟去钾」「两次透析之间体重增长不超过干体重 5%」「总量＝前一天尿量＋500 mL」。

这些数字**只作提醒，不是本仓库给出的医疗建议**，也不针对任何具体患者。每个人的干体重、血钾基线、用药方案都不同，一切以透析中心书面交代为准。工具不做判定、不推结论、不生成用药方案。

有一处口径已统一：低血糖救急**只用葡萄糖片或少量糖水，不用香蕉、橘子、果汁**——透析患者血钾容易高，用果汁救急会把钾一起升上去。参考模板里曾有一处低血糖提示写着「半杯果汁」，与它自己的应急卡和饮食页矛盾，本版已改正。

## 数据与隐私

- 全部内容写在本机 `localStorage`（键 `dialysis.v1`），**不上传任何服务器**。
- 清理浏览器缓存、换手机、卸载浏览器，数据就没了。**每周点一次「导出备份文件」是硬要求，不是客气话**，备份存到微信收藏或网盘。
- 新版导出两类文件：完整 JSON 备份（可「导入备份 / 恢复」）、纯文本记录（`.txt`，发给医生或打印）。
- 默认所有档案为空：不预填姓名、不预填任何个人健康数值。
- 详见 **[docs/PRIVACY.md](docs/PRIVACY.md)**。贡献者请务必先读，PR 里不要出现任何真实患者数据。

│   ├── link-titles.json        # 60 条链接的标题索引

**改源码，别直接改根目录的 HTML**——它们是构建产物，下次构建会覆盖。

```bash
python tools/build.py
```

构建会自检：外部资源引用、占位符是否替换干净、链接与标题条数（38 + 22）、页面间链接是否存在、脚本闭合、隐私关键词、机构标识、来源与存疑残留、ASCII 文件名。任何一项不过就不写产物。只需 Python 3，无第三方依赖。

根目录 6 个 HTML 全部提交进仓库，这样 GitHub Pages 能直接用，也能整目录拷到手机。

## 配套 Skill

`skill/` 是给 AI 立的规矩：工具负责存数据，Skill 负责「怎么说话、什么时候闭嘴」——只描述事实与变化、急症先让打电话、生成就诊摘要与待问医生清单；不诊断、不推测病因、不建议剂量、不解释化验单、不拿「应该没事」糊弄人。

**怎么用**：在工具里点「导出备份」拿到 `.json`，把内容贴给 AI 或直接给路径，再说一句要什么就行。四句现成的话：

- 「看看这几天的记录，哪些没记全」
- 「把最近几次血糖整理一下」
- 「刚下机人有点迷糊，要不要紧」
- 「下周三复诊，帮我整一页纸」

`skill/SKILL.md` 第 7 节是完整帮助（能干什么、三步起步、不接的活、易踩的坑）；`skill/references/examples.md` 有四个端到端例子，把家属原话、虚构输入、AI 完整回复和逐条规则对照摆在一起，照着改最省事。

安装：把 `skill/` 整个目录复制到 `~/.workbuddy/skills/dialysis-care/`（**建真实目录，不要用软链**）。Skill 只处理使用者主动导出的 JSON，不读取本机浏览器存储。

## 知识链接的已知边界

- **60 条标题只作索引**，存在 `data/link-titles.json`，与 `qr-links.json` 用同一套编号配对。工具不解释链接内容、不补写剂量与用法。
- **链接正文没有抓取，也抓不到**：药物表 38 条是草料活码短链，宣教树多为微信内内容或短链中转页，浏览器打开的常常只是中转页。本仓库只做标题索引，不解释内容、不补写剂量。打不开时可复制链接在微信里打开、换设备打开，或直接扫海报原图。
- 海报原图版权归原作者，默认不入库；确认可公开分发后再单独添加。
