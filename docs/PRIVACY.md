# 隐私与数据安全

这份文件比功能说明更重要，请在使用和贡献之前读完。

## 数据存在哪

- 全部记录只写在使用者本机的浏览器 `localStorage`（键 `dialysisCare.v1`）。
- 没有后端、没有账号、没有云同步、没有统计脚本、没有外部字体或 CDN。
- 工具不会主动打开外链；知识页里的链接只在点击时才跳转。
- 手机清缓存、换设备、微信内置浏览器清数据，都可能抹掉本地记录。**每周导出一次 JSON 是硬要求，不是可选项。** 首页在超过 7 天没备份时会提醒一次。
- 浏览器隐私模式下可能不允许写入本地存储。工具会明确提示「请立即导出 JSON 备份」，不会假装已保存。

## 导出文件怎么处理

导出的 JSON / CSV 含姓名、血糖、血压、化验值等健康信息，属于个人敏感数据：

- 存在自己设备里，别发到群里、别提交到任何仓库；
- 打印件是给医生和透析室看的，用完收好；
- 仓库的 `.gitignore` 已把 `*备份*.json`、`dialysisCare-*.csv`、`/exports/`、`/backups/` 等挡掉。别为了图方便去掉这些规则。

## 给贡献者的红线

**Pull Request 里不要出现任何真实患者数据。** 包括：真实姓名、病历号、医院就诊资料、检查报告、化验单照片、带数值的截图、导出的记录文件。测试数据一律用明显虚构的值（例如 `示例 99.9`），并在 PR 描述里说明是演示数据。

维护者合并前会检查：

- 有没有 `*.docx` / `*.pdf` / `*.xlsx` / 图片被带进来；
- 有没有真实姓名、病历号、身份证号、手机号（海报上公开的业务电话除外）；
- 有没有把真实记录写进 `data/*.json` 或测试用例。

发现误提交的敏感信息，不要只改文件——要联系仓库所有者清理历史提交。

## 海报链接与图片

`data/qr-links.json` 里的 60 条链接来自医院公开宣教海报上的二维码解码，只作索引：

- 主题名、药名、剂量**没有**逐条核对，仓库不猜测、不补写、不解释；
- 部分链接是微信内内容或活码中转页，浏览器可能打不开正文；工具提供复制链接、自定义备注和「扫医院原海报」三条兜底路径；
- 海报原图版权归原作者/医院所有，默认不入库（`/assets/posters/` 已被忽略）。确认可公开分发后再单独添加；
- 药物表里抄录的药学部业务电话是海报上的公开信息，工具里做成可编辑字段，方便各家医院改成自己的号码。

## 医疗免责

本工具用于日常护理记录与就诊沟通，**不构成医疗建议、不用于诊断或治疗决策**，也不是医疗器械。它不内置任何血糖阈值、监测间隔、补糖量或透析参数；这些一律由主管透析中心书面交代后由家属自行填写。

出现急症请立即联系透析中心或拨打 120，不要等工具提示，也不要按工具里的任何文字自行处置。
