# 隐私与数据安全

这份文件比功能说明更重要，请在使用和贡献之前读完。

## 数据存在哪

- 六张页面共用一份本机浏览器 `localStorage`（键 `dialysis.v1`）：号码、每日记录、药单、排班、打包勾选、复诊问题、夜间模式都在里面。
- 没有后端、没有账号、没有云同步、没有统计脚本、没有外部字体或 CDN。
- 工具不会主动打开外链；知识页里的 60 条链接只在用户点击时才跳转。
- 手机清缓存、换设备、微信内置浏览器清数据，都可能抹掉本地记录。**每周导出一次备份是硬要求，不是可选项。**
- 浏览器隐私模式下可能不允许写入本地存储。此时页面会提示「保存失败，浏览器可能禁用了本地存储」或「这台浏览器不允许本地保存」，不会假装已保存。请改用系统浏览器并添加到主屏幕后再用。

## 导出文件怎么处理

导出的 JSON 备份与文本记录含吃药清单、血糖、血压、体重等健康信息，属于个人敏感数据：

- 存在自己设备里，别发到群里、别提交到任何仓库；
- 打印件是给医生和透析室看的，用完收好；
- 仓库的 `.gitignore` 已把 `*备份*.json`、`dialysisCare-*.csv`、`*记录导出*.csv`、`/exports/`、`/backups/` 等挡掉。别为了图方便去掉这些规则。

## 给贡献者的红线

**Pull Request 里不要出现任何真实患者数据。** 包括：真实姓名、病历号、就诊资料、检查报告、化验单照片、带数值的截图、导出的记录文件。测试数据一律用明显虚构的值（例如 `示例 99.9`），并在 PR 描述里说明是演示数据。

维护者合并前会检查：

- 有没有 `*.docx` / `*.pdf` / `*.xlsx` / 图片被带进来；
- 有没有真实姓名、病历号、身份证号、手机号（海报上公开的业务电话除外）；
- 有没有把真实记录写进 `data/*.json` 或测试用例。

发现误提交的敏感信息，不要只改文件——要联系仓库所有者清理历史提交。构建脚本 `tools/build.py` 每次也会扫一遍仓库文本里的隐私关键词，命中就不写产物。

## 海报链接与图片

`data/qr-links.json` 里的 60 条链接来自公开宣教海报上的二维码解码，只作索引：

- **60 条标题只作索引**，存在 `data/link-titles.json`。仓库不写剂量、不解释内容、不补写用药信息。
- 部分链接是微信内内容或活码短链中转页，浏览器可能打不开正文；可在微信里打开、换设备打开，或直接扫海报原图。
- 海报原图版权归原作者所有，默认不入库（`/assets/posters/` 已被忽略）。确认可公开分发后再单独添加。
- 海报上原有的机构业务电话、科室抬头等可识别信息**一律不入库**，知识页也不展示；应急页的号码由使用者自行填写，只存本机。

## 医疗免责

本工具用于家庭照护的提醒与记录，**不构成医疗建议、不用于诊断或治疗决策**，也不是医疗器械。

页面里保留的常见照护数值与应急步骤（例如 3.9 mmol/L、15 g 葡萄糖、焯水去钾、饮水量公式）来自公开的家庭照护要点，只作提醒，不针对任何具体患者；每个人的干体重、血钾基线、用药方案都不同，一律以主管肾内科医生和透析中心书面交代为准。

出现急症请立即联系透析中心或拨打 120，不要等页面提示。
