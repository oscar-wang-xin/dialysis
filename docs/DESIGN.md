# 设计说明（脱敏版）

> 这份文档解释「为什么这样设计」。仓库里不含任何真实病历、姓名或个人健康数值；文中提到的场景是一类普遍存在的家庭照护情形，不指向任何具体个人。

## 1. 定位与边界

给**透析患者和家属**用的家庭照护提醒与记录工具，不是给医生看的临床系统，也不是医疗器械。

- 做什么：把每天的数值、症状、吃药、出门、复诊记清楚；把应急步骤摆在手边；把公开宣教资料做成能搜的索引。
- 不做什么：不诊断、不推测病因、不解释化验单、不给处方剂量、不调整透析参数、不做危急值判定。
- 出状况时只给一个明确动作：联系透析中心或拨打 120。

配套的 Skill 已独立成仓 [xin-dialysis-skill](https://github.com/oscar-wang-xin/xin-dialysis-skill.git)（名 `xin-dialysis`）：工具负责存数据，Skill 负责「怎么说话、什么时候闭嘴」，并把本工具知识页的 60 条索引与常识内容一并收进去。两者分开维护，分工不能混。

## 2. 为什么是六张独立页面

这一版以工作区「透析」目录下那套家庭照护工具为**模板与功能基线**，形态是「离线工具包」而不是单页应用：

- 一张封面 + 五张各管一摊的独立 HTML，靠相对链接互相跳转；没有路由、没有框架、没有构建产物之外的运行时。
- 整目录拷到手机、用系统浏览器打开、添加到主屏幕，断网照用。老人不用记路径，出事时点桌面图标就能找到应急那一页。
- 每张页面都是**自包含单文件**：样式和脚本全内联，没有 `<link>`、没有外部字体、没有图片请求。知识页的 60 条链接只在用户主动点击时才跳转。
- 六张页面共用一份 `localStorage`（`dialysis.v1`），所以号码、记录、排班、夜间模式在页面之间是通的。

窄栏 `max-width:520px` 是刻意的：这套工具主要躺在手机浏览器里，桌面打开也保持同一栏宽，不拉成宽屏仪表盘。手机自适应单列，375px 与 1280px 都不横滚。

## 3. 信息架构

| 页面 | 主要动作 | 明确不做 |
| --- | --- | --- |
| 封面 `index.html` | 五个页面入口、先填号码的提醒 | 任何数据录入 |
| 综合卡 | 应急 / 饮食 / 记录 / 陪护 / 说明，底部五板块 Tab | 病情结论、健康评分 |
| 应急速查卡 | 深色大字，七种情况从症状到步骤，顶上 120 | 鉴别诊断、药物推荐 |
| 每日记录 | 台账、体重与血糖走势、导出、打印 | 自动判定高低、解释指标 |
| 照护知识 | 常识卡、三级排查、问题清单、60 条链接、搜索 | 偏方、剂量、把外链当本工具结论 |
| 使用说明 | 装桌面、头三天、每天怎么用、数据会不会丢 | — |

知识内容从上一版的单页应用里**完整搬过来**，单独成一张「照护知识」页：9 张常识卡、红黄绿三级排查、5 条常见情况速查、22 条宣教链接 + 38 条药物链接（每条带标题）、打开链接的兜底提示。搜索框同时过滤常识卡、排查卡、清单行和链接条目，命中折叠卡会自动展开。

## 4. 数据契约

本地存档键 `dialysis.v1`，六张页面读写同一份对象：

```
theme       light / dark
tels        { dialysis, doctor, family }
records[]   date, wPre, wPost, weight, bp, glu, gluAt, urine, uf, symptoms[], note
meds[]      name, time, dose, note
schedule    { days[], time }
packed[]    已勾选的出门清单项
visit       { date, dept, q }
backupAt    上次导出备份时间
lastTab     综合卡上次停留的板块
```

- 综合卡与每日记录页写 `records`，应急速查卡读 `tels`，封面与使用说明页读 `theme`。
- 导入备份前做格式校验，读不出来给明确提示，不覆盖现有数据。
- 默认所有档案为空：不预填姓名、不预填任何个人健康数值。
- 导出两类文件：完整 JSON 备份、纯文本记录（给医生看或直接打印）。

## 5. 关于页面里的医学数值

参考模板里含常见公开照护要点，例如「低于 3.9 mmol/L 补 15 g 葡萄糖」「蔬菜焯水 3 分钟去钾」「总量＝前一天尿量＋500 mL」「两次透析间体重增长不超过干体重 5%」。本版**照模板保留**，并在 README、使用说明、免责条里明写：这些只是提醒，不针对任何具体患者，一切以透析中心书面交代为准。

这与上一版「一个医学数值都不内置」的口径不同，是换模板带来的取舍，如实记录在 CHANGELOG。工具本身仍**不做数值判定结论**：台账里低于 3.9 的点标红、输入时弹一条提醒，文案只说「先测、先联系、按医生交代处理」，不写「你低血糖了」这种诊断式判断。

### 统一了一处真实冲突

参考模板的综合卡曾有一句低血糖提示写「补 15 g 葡萄糖（3 块方糖／**半杯果汁**／一勺蜂蜜）」，而同一套工具的应急卡、饮食页都明确写「不要用香蕉、橘子、果汁救急，钾太高」。透析患者血钾容易高，这不是措辞问题。本版把所有低血糖提示统一为**葡萄糖片或少量糖水**，并保留「不要用果汁」的提醒。

## 6. 修掉的模板缺陷

照抄模板不等于照抄 bug，以下三处是实测发现后修的：

1. **每日记录页的 `renderGluTrend()` 未定义**：页面有血糖走势的 SVG 容器，删除记录时会调用这个函数并抛 `ReferenceError`，初始化也没渲染它。本版补齐函数（3.9 虚线、低值红点）、在保存 / 删除 / 初始化三处都调用。
2. **血糖低于 3.9 的即时提醒从未触发**：容器在，但没有 `syncGluWarn()` 和输入监听。本版补齐，并统一上面那条口径。
3. **导出文本丢了测量时点**：`gluAt` 存进了记录，导出时却没带上。本版补进文本行，并让「清空」一并复位时点与提醒。

## 7. 视觉令牌

方向：**暖纸底 + 深墨绿 + 宋体大标题**，安静、像一本随手翻的照护手册，不做霓虹、不做 AI 紫粉渐变、不用 emoji 当图标。

| 项 | 规格 |
| --- | --- |
| 底色 / 纸面 / 正文 | `#F4F1E9` / `#FFFCF5` / `#1A1E1C` |
| 深墨绿 / 主色 | `#16302B` / `#1F6E63`（夜间 `#5AA99A`） |
| 砖红（只用于危重信号） | `#9E3A2C`（夜间 `#D97261`） |
| 标题字体 | 宋体栈 `"Songti SC","Source Han Serif SC","Noto Serif SC","SimSun",serif` |
| 正文 / 数字 | 系统中文栈 / 等宽数字栈；数字用等宽对齐 |
| 封面 | 深绿底 + 输液管细纹（46px 重复竖线）+ 右上柔光，底部圆角 22px |
| 卡片 | 纸面 + 1px 暖灰边 + 三层柔和阴影，圆角 8px；编号 kicker 用等宽小字 |
| 组件 | 电话块、编号步骤 `ol.steps`、食物清单、症状 chips、周排班按钮、checklist、折叠 `details` |
| 字号 | 正文 17px、行高 1.62；应急速查卡正文 18px、步骤 17px；辅助文字 ≥ 12.5px |
| 触控 | 主按钮 ≥ 44px、拨号按钮 ≥ 50px、导航 Tab 五等分；数字输入 `inputmode="decimal"` |
| 主题 | 默认浅色，右上角月亮按钮切夜间并记住选择，六页同步 |
| 动效 | 只留 180–250ms 的位移与渐显，尊重 `prefers-reduced-motion` |
| 图标 | 全部内联 SVG（Phosphor 路径），无图标库、无外部字体 |

状态一律配文字与形状（「危」「急」「注意」），不只靠颜色，黑白打印与色觉障碍下都能读。

## 8. 构建与打印

**源码拆分、成品自包含**：`src/*.tpl.html` 是模板，`data/*.json` 是知识数据，`tools/build.py` 把数据内联进知识页占位符、输出根目录 6 个 HTML，并做六类自检（外部资源、占位符、链接与标题条数、页面间链接、脚本闭合、隐私关键词）。改模板后跑一次构建即可，别直接改根目录成品。

打印样式与屏幕样式隔离：每日记录页隐藏底部工具栏与表单按钮，只留台账与走势；知识页隐藏搜索框、打印/夜间按钮和返回条，深色封面变白底黑字，折叠卡内容强制展开。A4 黑白清楚。

## 9. 验收

手机 375px 与桌面 1280px 都不横滚、六个页面互相跳转正常、控制台 0 报错、无任何自动外部请求；保存号码后应急速查卡能直接拨；记录一笔后端到台账、体重与血糖两张走势都更新；删除记录不报错；知识页搜「苯磺酸」精确命中 2 条、搜「钾」命中「『钾』的无声威胁」；夜间模式跨页同步；导出文本与 JSON 备份文件名正确；打印媒体下工具栏隐藏、底色转白。

## 10. 隐私默认

默认档案全空、不上传、不联网回传。仓库的 `.gitignore` 把病历文件、就诊资料、图片、导出备份、浏览器测试截图全部挡在门外——健康记录一旦进了公开仓库，就撤不回来了。构建脚本每次都会扫一遍隐私关键词，命中就不写产物。详见 `docs/PRIVACY.md`。
