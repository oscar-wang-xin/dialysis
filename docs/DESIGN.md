# 设计说明（脱敏版）

> 这份文档解释「为什么这样设计」。仓库里不含任何真实病历、姓名或健康数值；文中提到的场景是一类普遍存在的护理情形，不指向任何具体个人。

## 1. 定位与边界

这是给**透析患者和家属**用的护理记录与陪护辅助工具，不是给医生看的临床系统，也不是医疗器械。

- 做什么：把每天和每次透析的数值、时刻、症状、进食、处置记清楚；把趋势画出来；把要说给医生听的话整理成一页纸。
- 不做什么：不诊断、不推测病因、不解释化验单、不给用药剂量、不调整透析参数、不做危急值判定。
- 出状况时只给一个明确动作：联系透析中心或拨打 120。

配套的 `skill/` 是给 AI 立的规矩：工具负责存数据，Skill 负责「怎么说话、什么时候闭嘴」。两者分工不能混。

## 2. 为什么血糖监护是一级主线

透析过程中血糖会变化，只在上机时测一次看不出后半程；透析后期与透析后一段时间是重点观察窗口。对家属最有用的不是「今天血糖多少」，而是**「是不是每次都在同一段掉下来」**。

所以监护会话的横轴不是日历日期，而是：

```
已透析 X 分钟  /  剩余 Y 分钟
```

每个血糖值、每个症状、每次加餐都落在同一条进程轴上。历次曲线叠在同一坐标系里，发作时段分布一眼可见。这张图和按分钟排的监护单，是复诊时最能帮到医生的东西。

由此推出六个必须为它让路的地方：首页常驻监护条、透析当天的主行动按钮、记录数据里的进程字段、趋势图里的叠加视图、排查清单里的症状时刻、打印里的监护单；再加 Skill 里的血糖时序解读模板。

## 3. 四条硬规矩

1. **不内置任何医学数值。** 血糖阈值、监测间隔、加测点、补糖量、透析液参数，一个都不写死。`monitoring` 与 `targets` 全部留空，由家属照透析中心书面交代填写，并留一栏记「谁交代的」。公开资料里能查到各种间隔与阈值，来源多为二手转述、彼此也不一致；家里用的东西只认主管医生写下来的那条线。
2. **提醒只说「该测血糖了」，不说「你低血糖了」。** 没填提醒线就完全不做数值判定；填了也只标「低于你设的线」，不弹诊断式警告。
3. **不承诺后台推送。** 手机浏览器切后台会冻结计时器，页面提醒只在工具打开时有效。文档与界面都明写这一条，并建议用手机自带闹钟兜底。
4. **症状出现即现场处置。** 监护页第一按钮是「告知透析室工作人员」，第二按钮才是记录；不替代现场医护、不远程指挥。

## 4. 信息架构

底部四个 Tab：今天 / 记录 / 排查 / 知识。数据与设置从右上角进入，不占 Tab。层级最多两层，任何页面两次点击能回到首页。

| 页面 | 主要动作 | 明确不做 |
| --- | --- | --- |
| 今天 | 看监护条、记一笔、进入血糖监护、就诊摘要、备份 | 健康评分、结论式判断 |
| 记录 | 每日记录、透析日志、化验、用药、趋势 | 自动判定高低、解释指标 |
| 排查 | 按症状找核对清单、拨号 | 鉴别诊断、推荐药物 |
| 知识 | 内置常识卡、宣教与药物链接索引、搜索 | 偏方、剂量、把外链当本工具结论 |
| 数据与设置 | 档案、目标范围、监护配置、导入导出、打印 | 上传、账号、云同步 |

## 5. 数据契约

本地存档键 `dialysisCare.v1`，结构见 `src/app.js` 的 `defaultState()`。要点：

- `sessions[].timeline[]` 里每个点带 `elapsedMin / remainMin / glucose / meal / sbp / dbp / symptom / action / note`；`glucose` 可以是 `null`，表示这一条只记了症状或加餐。
- `profile.targets` 与 `profile.monitoring` 默认全空，空值即「不做任何数值判定」。
- `profile.lastBackup` 记录上次导出时间，超过 7 天在首页给一次温和提醒。
- 导入 JSON 前二次确认，并自动留一份旧快照在内存里供当次撤销。

## 6. 技术选型

**源码拆分、成品单文件。** 这是为了同时满足两件互相打架的事：开源项目要好维护，使用者要「双击就能开」。

- `src/shell.html` + `src/app.css` + `src/app.js` + `data/*.json` 是源码；
- `tools/build.py` 把样式、脚本、知识数据内联，生成根目录 `index.html`；
- `index.html` 是提交进仓库的交付物，零外部请求、无构建依赖、无后端、无账号、file:// 下可用。

图表用手写 SVG 折线，不引图表库；字体用系统中文栈，不引外部字体；所有外链只在用户主动点击时打开，工具本身不预加载、不请求任何资源、不含统计脚本。

## 7. 视觉令牌

| 项 | 规格 |
| --- | --- |
| 主色 / 平稳 / 底色 / 正文 | `#0891B2` / `#059669` / `#F3FAFC` / `#123B47` |
| 留意 / 紧急 | `#B45309` / `#C62828` |
| 字号 | 正文 17px、行高 1.75；关键数值 28–32px；辅助文字不低于 14px |
| 触控 | 按钮最小 48×48px，相邻间距 ≥ 8px，数字输入 `inputmode="decimal"` |
| 状态 | 不靠颜色单独表意，一律配文字与形状；黑白打印、色觉障碍下都能读 |
| 动效 | 150–250ms 轻微反馈，尊重 `prefers-reduced-motion`，不做入场动画 |
| 主题 | 默认浅色，另给「高对比大字」开关（不动数据） |

## 8. 打印

四种 A4 视图共用一套打印样式：周记录表、透析事件单、就诊摘要、透析中血糖监护单。手机走系统分享里的打印或存成 PDF。页脚固定印「仅供就诊沟通参考，非医疗诊断」。

## 9. 验收

手机 375px 不横滚、微信内置浏览器可开、Chrome 打印预览可读、A4 黑白可辨、离线飞行模式可用、控制台无报错、无任何外部请求。再走一遍「导出 JSON → 清空 → 导入」，数据要能完整还原。

## 10. 隐私默认

默认档案全空：不预填姓名、不预填任何数值、不上传。演示数据必须明标「演示数据」且可一键清除。仓库的 `.gitignore` 把病历文件、就诊资料、图片、导出备份全部挡在门外——因为健康记录一旦进了公开仓库，就撤不回来了。详见 `docs/PRIVACY.md`。
